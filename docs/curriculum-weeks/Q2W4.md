# Q2W4 — Curriculum Guide Extract

Q2W4 Weekly preparation

Add a local room form and filter

Starting point: The page displays a read-only source-defined room list.

End-of-week check: A filter and validated add-room form update browser state only.

Explain these ideas before the build

State lets a screen respond to input. Filtering selects visible records without deleting them. A controlled input keeps its displayed value in React state. Adding a room changes this browser session only; a refresh resets it until persistence is built later. Basic validation rejects a blank name and a nonpositive or noninteger capacity. Client validation helps the user but will not replace server checks when an API is added.

state: A value the screen remembers while it runs.

input: Information a user enters.

validation: Checking whether input follows a rule.

Prepare this week in order

1. Confirm the previous checkpoint works. Prepare Art, xyz, a blank name, and capacities 20, 0, and 2.5. Keep the current two-room list available; no form or filter has been prepared.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Define separate acceptance checks for filter and add-room behavior. Students decide what is in scope for a local prototype.

4. Improve the prompt by focusing on this skill: Specify boundaries: input, valid example, invalid example, and the fact that refresh resets local changes.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.
