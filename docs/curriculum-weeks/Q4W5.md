# Q4W5 — Curriculum Guide Extract

Q4W5 Weekly preparation

Repair required defects and verify boundaries

Starting point: User acceptance has produced a prioritized list of real findings.

End-of-week check: Required blockers are fixed and retested; server and data boundaries pass review.

Explain these ideas before the build

A repair should target observed evidence and preserve working behavior. Authorization must run on the server for every protected operation. Data integrity must survive direct API requests and simultaneous writes. Dependency review can identify issues, but changes still need tests. If there are no required defects, use the same time for the full boundary checks rather than inventing features.

regression: A change that breaks previously working behavior.

least privilege: Giving each role only its needed access.

dependency: A library or service the app relies on.

Prepare this week in order

1. Confirm the previous checkpoint works. Select the highest-priority reproducible defect and a safe test environment. Have the latest backup and current commit recorded. Do not test destructive operations on live school data.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Limit each repair branch to one issue. A task becomes Done only after its original failure and related regression checks pass.

4. Improve the prompt by focusing on this skill: Use action, expected, actual, relevant files, and constraints in a repair prompt. Ask for a minimal diff and explanation.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.
