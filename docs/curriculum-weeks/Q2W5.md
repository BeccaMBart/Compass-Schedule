# Q2W5 — Curriculum Guide Extract

Q2W5 Weekly preparation

Build the API and connect the room screen

Starting point: Room additions exist only in React state. There is no backend.

End-of-week check: FastAPI owns a temporary room list; React reads and creates rooms through requests.

Explain these ideas before the build

An API separates screen code from server behavior. GET reads data; POST requests creation. HTTP status codes describe the response. FastAPI validates input using models; invalid requests must be rejected even if a browser check is bypassed. This week the server uses temporary memory and loses additions when restarted. Replace the old frontend array rather than retaining a hidden alternate app. Loading and error states tell the user what happened.

request: A message asking a server to do something.

response: The server reply to a request.

API: An agreed way for programs to communicate.

Prepare this week in order

1. Confirm the previous checkpoint works. Verify Python 3.12 and a working terminal. Follow the backend environment procedure during Monday class. Prepare a route card for GET /rooms and POST /rooms.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Write a two-route contract before implementation: method, path, input, successful result, and rejected result.

4. Improve the prompt by focusing on this skill: Supply an interface contract and request only the current route. Use actual errors to refine a repair prompt.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.
