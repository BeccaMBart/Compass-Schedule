# Q2W7 — Curriculum Guide Extract

Q2W7 Weekly preparation

Build teachers courses and class sections

Starting point: Only rooms can be created and stored.

End-of-week check: Administrators can create and edit catalog records for rooms, teachers, courses, and sections locally.

Explain these ideas before the build

A course names a subject; a section identifies one taught group with a teacher and planned seat limit. A relationship stores an ID rather than copying a name. Foreign keys protect references, but application rules still check meaningful values. Schema changes now use reviewed migrations. Existing rooms must survive adding new tables. Editing is needed for a usable product; deleting referenced records must be rejected or deliberately archived rather than silently breaking meetings.

course: A subject such as Algebra.

section: One offered group of a course.

relationship: A link between records using an ID.

Prepare this week in order

1. Confirm the previous checkpoint works. Prepare T1 Alex Example, T2 Jordan Example, Algebra, Art, Section A with limit 24, and Section B with limit 18. Rehearse migration vocabulary, not future feature code.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Use a dependency order: teacher/course records before sections. Split forms and routes into small cards.

4. Improve the prompt by focusing on this skill: List allowed model fields and explicitly exclude enrollment and scheduling until their week.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.
