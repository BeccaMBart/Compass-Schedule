# Q2W2 — Curriculum Guide Extract

Q2W2 Weekly preparation

Plan the product and create its first page

Starting point: Only the existing README and Git history exist.

End-of-week check: A scoped project board, a minimal React page, and reviewed student commits.

Explain these ideas before the build

A repository stores the source and its history; it is not a running application. A requirement describes an observable user outcome. An acceptance check says how we will recognize success. A prompt needs current state, one requested change, constraints, and a check. React displays the first page; Vite runs the development server. A package file lists dependencies, while the lockfile records resolved versions. Nothing beyond a heading and purpose sentence is implemented this week.

requirement: A clear statement of what a user needs.

prompt: The instructions and context given to AI.

commit: A recorded group of source changes in Git.

Prepare this week in order

1. Confirm the previous checkpoint works. Verify VS Code, Git, Node 22.12 or later within the Node 22 line, and npm. Open the README-only repository. Prepare a blank task card and projector. Confirm the school owner can provide Microsoft test identities, Azure access, and a VPS/domain by the later milestone dates. Do not create app files before class.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Create Backlog, Ready, Doing, Review, and Done columns in docs/board.md. Limit Doing to one class build task. Name an owner and one acceptance check for each card.

4. Improve the prompt by focusing on this skill: Improve Build my app into a bounded request for one page. Students identify the missing audience, current files, scope, and success check.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.

Then create scripts/classroom-context.sh and paste the entire helper below. This reads current files into a temporary text attachment; it implements no application feature.

#!/usr/bin/env bash
set -euo pipefail
cd "$(git rev-parse --show-toplevel)"
{
  printf '%s %s current source\n' "${1:-Current}" "${2:-lesson}"
  git status --short
  git log -1 --oneline
  git ls-files
  git ls-files --cached --others --exclude-standard -- \
    README.md 'docs/*.md' 'frontend/*.json' \
    'frontend/*.html' 'frontend/*.js' 'frontend/src/*' \
    'backend/*.py' 'backend/*.txt' 'backend/alembic.ini' \
    compose.yaml Dockerfile .dockerignore .gitignore \
    'deploy/*.yaml' deploy/Caddyfile '.github/workflows/*' \
    | sort -u | while IFS= read -r course_file; do
      printf '\nFILE %s\n' "$course_file"
      cat "$course_file"
      printf '\n'
    done
} > /tmp/class-scheduler-context.txt
printf '%s\n' 'Created /tmp/class-scheduler-context.txt'
