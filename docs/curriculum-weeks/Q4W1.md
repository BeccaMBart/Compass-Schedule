# Q4W1 — Curriculum Guide Extract

Q4W1 Weekly preparation

Prepare the permanent hosting environment

Starting point: The complete current app runs on Azure; backup and restore have been demonstrated.

End-of-week check: A school-owned VPS, domain, access plan, and reviewed deployment task are ready.

Explain these ideas before the build

A deployed application needs an owner as well as code. DNS points a school-controlled name to the server. HTTPS protects browser traffic. The VPS will run the same application image developed in class, with configuration suited to this host. PostgreSQL stays private. Preparing accounts, keys, billing, and a domain is an adult logistics task; it does not mean writing app features ahead of lessons.

VPS: A rented server managed by its owner.

DNS: The system that connects a name to an address.

TLS: The protection used by HTTPS connections.

Prepare this week in order

1. Confirm the previous checkpoint works. Confirm the approved VPS and domain are available. The teacher or IT owner controls payment, SSH keys, DNS, and recovery. Use the VPS steps printed in this week; keep credentials out of projected screens.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Assign one adult owner, one backup owner, and a due date to each hosting dependency. Treat missing access as a blocker, not a student homework task.

4. Improve the prompt by focusing on this skill: Give AI verified environment facts and ask it to identify missing inputs before suggesting commands. Never let it invent a domain or credential.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.

Prepare the server and DNS

1. Use the provider’s approved console/SSH connection instructions. Confirm the server identity and OS. Supply only public connection facts to today’s prompt so it can fill the exact SSH command; do not paste a private key.

2. Install Docker Engine and the Compose plugin using the official Ubuntu instructions for that server OS. On the server run docker --version and docker compose version. Do not confuse the remote server terminal with the Mac terminal.

3. In the domain’s DNS editor, set its A record to the actual VPS IPv4 address. Keep an AAAA record only if that IPv6 address is correctly configured. On the Mac run the exact dig command generated from vps-public.md and compare the result.

4. Permit 80/443 to the reverse proxy and restrict administration using the approved access method. Docker-published ports can bypass some host-firewall rules, so leave app/db ports unpublished. Do not open 5432 publicly.

Docker Engine on Ubuntu https://docs.docker.com/engine/install/ubuntu/
