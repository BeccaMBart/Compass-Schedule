# Q3W4 — Curriculum Guide Extract

Q3W4 Weekly preparation

Build timetable publication

Starting point: Admin edits a draft; Teacher has no approved timetable yet.

End-of-week check: Publishing validates the draft and saves a stable approved snapshot.

Explain these ideas before the build

Publication is different from deploying application code. An approved timetable must not change when an administrator edits the next draft. Store an immutable publication header and copied meeting labels, assignments, days, and periods, plus an active-publication pointer. In the same scheduling transaction, lock the active term, validate current data, save the snapshot, and advance the pointer. A failure leaves the old active version unchanged. Teacher reads use the snapshot and trusted teacher mapping.

draft: The working timetable administrators edit.

published: The approved timetable people can use.

version: An identifiable saved state of the timetable.

Prepare this week in order

1. Confirm the previous checkpoint works. Prepare a paper Draft A and Approved Version 1. Confirm role and transaction checks from prior weeks still pass.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Write the publish acceptance story before implementing the button. Treat draft/published separation as a required feature.

4. Improve the prompt by focusing on this skill: Describe an invariant: draft edits must not alter the already approved view.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.
