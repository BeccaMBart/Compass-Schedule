# Q4W3 — Curriculum Guide Extract

Q4W3 Weekly preparation

Practice backup  recovery  and support

Starting point: The permanent VPS hosts the required current app.

End-of-week check: Scheduled off-host backups, a tested isolated restore, and an owner-run support routine exist.

Explain these ideas before the build

A persistent volume is not a backup. A useful backup must be separate from the machine it protects and must be restorable. Restore drills use an isolated database, never the live database. Monitoring needs someone who reads alerts and knows what to do. A rollback also needs migration compatibility; blindly running older code against a changed schema may fail.

backup: A separate copy used to recover data.

restore: Loading a backup into a database.

monitoring: Checking service health over time.

Prepare this week in order

1. Confirm the previous checkpoint works. The adult owner approves off-host storage, access, retention, and a monitoring contact. Select fictional demonstration data for the restore exercise. Never give production secrets to students.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Assign backup, alert, patch, and restore duties to adults. Record recovery evidence and an agreed retention period.

4. Improve the prompt by focusing on this skill: Ask for a plan with preconditions, isolated targets, checks, and stop conditions before requesting operational commands.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.

Create and transfer a private VPS backup

Run on the VPS in its deploy directory. These commands create a custom-format dump inside db and copy it to a private directory outside the served files. Use a timestamped name so earlier backups are not overwritten.

mkdir -p "$HOME/class-scheduler-backups"
chmod 700 "$HOME/class-scheduler-backups"
course_backup="scheduler-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose -f deploy/compose.vps.yaml --env-file .env exec -T db pg_dump -U scheduler -d scheduler -Fc -f "/tmp/$course_backup"
docker compose -f deploy/compose.vps.yaml --env-file .env cp "db:/tmp/$course_backup" "$HOME/class-scheduler-backups/$course_backup"
chmod 600 "$HOME/class-scheduler-backups/$course_backup"

Use the approved destination’s encrypted transfer method to copy the backup off the VPS. Do not attach the dump to ChatGPT. Give today’s prompt the destination type, non-secret path, schedule, retention decision, and failure-contact details so it can generate the exact scheduled job.
