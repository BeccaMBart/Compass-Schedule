# Q3W2 — Curriculum Guide Extract

Q3W2 Weekly preparation

Build Microsoft sign in and protect the API

Starting point: The planner is a local unauthenticated prototype.

End-of-week check: Microsoft sign-in works and the API validates credentials for its own audience.

Explain these ideas before the build

Use the school-approved Microsoft tenant and maintained MSAL client libraries with authorization code and PKCE. Register a browser application and the API it calls. Public browser code must not contain a client secret. An ID token is not a substitute for an API access token. The API validates signature, trusted issuer/tenant, audience, lifetime, and required scope using maintained libraries and trusted metadata. Role assignment is a separate increment next week. Keep this transitional authenticated app local until authorization is complete.

identity: Who a person is.

sign in: Proving identity to a service.

credential: Evidence used to establish access.

Prepare this week in order

1. Confirm the previous checkpoint works. The school owner must supply the approved tenant/cloud, app registration rights or administrator assistance, and at least two test identities by this week. Use a separate admin-approved configuration record. Do not send tokens or secrets to AI.

2. Prepare the fictional records or paper examples named above. Prepare account/tool access only; do not implement this week’s app changes before the live lesson.

3. Practice this project-management action with students: Track an external dependency: tenant registration and consent. Verify access early; record blockers with an owner and date.

4. Improve the prompt by focusing on this skill: Separate public configuration from secrets. Supply actual platform details and ask for one identity boundary at a time.

5. Keep the three lessons below in order. If a check fails, use that lesson’s repair prompt and preserve the working data. Record failed or not-run checks honestly.

Student record for the week

Each student keeps one note with their name/pseudonym, role, prediction, small change or review, observed result, and one concept in their own words. Use docs/student-work/ for class evidence. The teacher remains responsible for the application and all account credentials.
