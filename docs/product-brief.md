# Class Scheduler — Product Brief

## Project

Class Scheduler

## Purpose

Build a web application that helps school staff
plan classes, teachers, rooms, and teaching periods.

## Target completion

Q4W8

## Intended users

- Admin: manages scheduling information,
  assignments, and publication.
- Teacher: accesses permitted scheduling
  information.

## Required final features

1. Manage rooms and their capacities.
2. Manage teachers.
3. Manage courses and class sections.
4. Assign classes, teachers, rooms, and fixed
   teaching periods manually.
5. Check scheduling conflicts on the server.
6. Check room capacity constraints.
7. Support Microsoft sign-in.
8. Enforce Admin and Teacher permissions.
9. Publish a stable, approved timetable.
10. Deploy the application to Azure for teaching.
11. Operate the completed application
    permanently on a VPS.

## Outside the project scope

- Student enrollment
- Individual student schedules
- Automatic timetable generation

## Development approach

Build the application incrementally.

Each lesson introduces only the approved task.
Students review, test, and commit small changes.

Future features remain in the Backlog until
their scheduled lessons.

## First build task

Create a simple React page containing:

Heading:
Class Scheduler

Purpose sentence:
We are building a tool to plan classes and rooms.

No forms, scheduling features, database, API,
authentication, or additional screens.

## First build acceptance criteria

- The page displays the exact heading.
- The page displays the exact purpose sentence.
- The page contains no additional app features.
- The React application runs locally.
- The production build succeeds.
- Existing README.md is preserved.
- Future features remain in the Backlog.
